Native MCP with per-user OAuth

TimeboardApp serves a Streamable HTTP MCP endpoint at /mcp inside the existing application. Each person signs in with their own Timeboard account and approves the requested permissions. Eleven tools support account identification, task search and summaries, task changes, and eligible assignment. No OpenAI API key or manually copied Timeboard bearer token is needed.

Enable it on your instance

  1. Follow the 00.14.00 upgrade steps. Build from the release source with the Dockerfile and Compose file in your checkout.
  2. In the supplied Compose .env, set the public HTTPS origin and opt-in flag shown below. The release Compose file passes both to the container. For a custom stack, add them to the service's environment block. Do not include /mcp in the base URL.
  3. Preserve Host and the original HTTPS scheme through your trusted reverse proxy. Forward the whole application, including discovery and OAuth paths. MCP uses the existing application port. A path prefix and public demo mode are not supported.
  4. Recreate the container, then verify discovery and the unauthenticated response. A restart alone does not install new source or apply changed Compose environment values.
# .env for the supplied release Compose file
TIMEBOARDAPP_BASE_URL=https://tasks.example.com
TIMEBOARDAPP_MCP_ENABLED=true

# Run in your release checkout after backing up persistent data.
docker compose up -d --build --force-recreate timeboardapp

curl -fsS https://tasks.example.com/.well-known/oauth-protected-resource/mcp
curl -i https://tasks.example.com/mcp

Replace the hostname with your own. Discovery should return JSON; the unauthenticated MCP request should return 401 Unauthorized with a WWW-Authenticate header. For YAML configuration, token lifetimes, and callback settings, see configuration.

Connect from ChatGPT

  1. Open ChatGPT's Plugins menu, choose +, then Add custom MCP server. Access depends on your account and workspace policy.
  2. Enter https://tasks.example.com/mcp, configure OAuth, and choose Create as a plugin. Timeboard publishes OAuth discovery metadata and supports dynamic client registration.
  3. The default callback allowlist is https://chatgpt.com/connector_platform_oauth_redirect. If the setup shows a different callback, copy that exact URL into mcp.allowed_redirect_uris in persistent settings and restart before registering. Never use a wildcard. Changing the callback or public origin can require a new connection.
  4. Sign in to Timeboard and review the account, requested scopes, and callback on the consent screen. Approve only the access you intend to grant.
  5. Start a new conversation and select the plugin with @. First ask it to identify your account and list tasks, then create one disposable test task. Confirm returned results and any write approvals.
  6. In Timeboard, open Profile → Connected applications and disconnect the test connection. Verify that further tool calls fail before reconnecting for regular use.

For disposable data, an isolated Compose project, and the full acceptance checklist, use MCP_TESTING.md. Automated protocol, browser, and container checks do not establish live ChatGPT acceptance for your account or public TLS deployment. This release has no embedded ChatGPT widget or plugin-directory approval.

Tools and permission boundaries

ScopeToolsAccess
tasks:readget_profile, list_tasks, get_task, task_summaryThe connected account and its own tasks, including for administrators.
tasks:writecreate_task, update_task, complete_task, archive_task, restore_taskOwned tasks using existing recurrence, subtask, and notification rules.
users:readlist_assignable_usersSelf and eligible subordinates; administrators may list all users. IDs and usernames only.
tasks:assignassign_taskTransfer an owned, active standalone task to an eligible assignee.

Each tool independently checks its scope and current permissions. Assignment cannot transfer tasks in a parent/child tree and does not grant access to the recipient's other tasks. Existing followers are removed on transfer; the recipient gets an in-app assignment notification. After transfer, the former owner loses MCP access to that task.

Listings are paginated with at most ten tasks and a response-size budget. Treat content_truncated as a warning not to overwrite complete stored text with a shortened read. Dates need a timezone offset. Task text and URLs are untrusted data, never instructions. Tools do not expose administrator settings, database exports, permanent deletion, or arbitrary URL fetching.

Creation and assignment require a stable request_key. Reuse the same key and identical arguments after a timeout; use a new key for a new action. Completion retries after success return a conflict, so read the current task state instead. Existing configured notifications may be sent by task changes.

Connection lifecycle

Authorization uses S256 PKCE and single-use codes. Tokens are bound to the exact configured MCP resource. Access tokens default to 15 minutes; refresh tokens rotate within a 30-day absolute connection lifetime. Replayed codes or refresh tokens revoke the connection. Password changes, account removal, signing-key rotation, and profile disconnection invalidate relevant access.

To disable MCP, set TIMEBOARDAPP_MCP_ENABLED=false and recreate the container. With no environment override, change mcp.enabled in settings and restart. MCP, OAuth, and connection routes disappear. Stored grants are retained, so disconnect first if re-enablement should require new consent. Full SQLite/settings backups preserve OAuth and retry state; JSON exports omit it and require reconnecting after a fresh restore.

Existing private GPT Actions

The separate GPT Actions interface remains supported and does not require MCP. It provides eight owner-only operations: list/search, summary, read, create, update, archive, complete, and restore. Its generated schema is /openapi-chatgpt.json, which returns 503 until a public HTTPS base URL is configured. It does not provide task assignment.

  1. Configure TIMEBOARDAPP_BASE_URL on the application deployment. Do not use this static website as the API origin.
  2. Authenticate to POST /api/auth/token through a trusted client. Use that access token to call POST /api/integrations/tokens with a descriptive name, expiry of 1–90 days, and allow_write (false by default).
  3. Save the one-time tba_... token in the GPT editor's Action authentication setting as an API key using Bearer authentication. Never put it in instructions, the schema, or a conversation.
  4. Import your deployment's /openapi-chatgpt.json schema. Keep the custom GPT private: a shared API-key-backed GPT acts with the token owner's access.
  5. Test reads, ownership isolation, pagination, and write rejection before enabling writes. Approve one disposable creation/completion, revoke the token, and verify that access fails.
POST /api/integrations/tokens
Authorization: Bearer <your-short-lived-access-token>
Content-Type: application/json

{"name":"Private task assistant","expires_days":30,"allow_write":false}

These integration tokens are hashed at rest, expire, can be individually revoked through DELETE /api/integrations/tokens/{id}, and stop working after a password change/reset. They cannot authenticate to MCP or the original administrator API. All Action writes carry x-openai-isConsequential: true; client confirmation annotations do not replace server authorization.
